# 进化信号构造（Evolution Signals under Weak Evaluators）

> **一句话结论**：change-001 时点"弱评估器下的自进化几乎空白"的判断**不成立，须修正为部分空白**——2025 下半年起该问题已成热点并形成五条成熟路线（rubric 化 judge 奖励、评估器共进化、内在/一致性信号、人类偏好回流、弱 verifier 集成），权重层甚至已"卷"起来（EvoRubric/EvoRubrics/SERPO/SCORE/HOTE 五篇共进化工作三个月内密集出现），harness 层也有首篇直接工作 TTHE；**剩余真空**是三个交集：(a) harness/记忆/技能层自进化 × 真不可验证任务域，(b) 信号可靠性感知的进化治理（何时信 judge/一致性/召回人类），(c) 长周期延迟结果信号（EvoScore 类 repo 健康度量）回流为进化信号的闭环。立项须从"开荒"改为"在密集相关工作中做精确差异化"。

## 五条信号路线（+ harness 层）

1. **LLM-as-judge / rubric 化奖励**（权重层为主，已过"能不能做"进入"怎么做稳"）：Rubrics as Rewards（2025）开路，2026 年形成完整生态——rubric 生成改进、coach 化富反馈（LLM-as-a-Coach：judge 的富文本评估蒸馏为经验知识而非标量）、Rubric Dropout（每步随机丢准则缓解 hacking）。
2. **评估器与被评者共进化**（直面"judge 天花板"，竞争最激烈的子方向）：EvoRubric（单策略分饰 Reasoner/Rubric Generator + 多级验证）、EvoRubrics（对抗共进化）、SCORE（evaluator-solver 共享参数共进化）、SERPO（判别性准则进化 + verdict-token 概率作奖励）、HOTE（proposer/solver/judge 三方混合 RL）——全部在权重层。
3. **内在信号 / self-consistency**（无任何外部 judge）：TTRL（多数投票伪标签，预设唯一正确答案）、Intuitor（self-certainty）、G-Zero（Hint-δ：提示引起的对数似然偏移，纯内在，标题级匹配"unverifiable domains"）。局限：置信度可被过度自信污染，与"人类眼中的好"的对齐只有间接证据。
4. **人类偏好回流**（部署期隐式信号）：Echo（用户对 agent 输出的后续修改序列 = 事后金标，需海量流量）、SLIFT（自然反馈分解为 Fix/Spec/Null 原子成分选择性自学习）。
5. **弱 verifier 理论与集成**：Weaver（NeurIPS 2025，弱监督估计各弱 verifier 准确率后加权集成，近 oracle 选答——但停在 best-of-N，未接入进化闭环）。

**harness 层（路线六，与本项目最直接相关）**：TTHE（2026）是唯一直接工作——测试时用无标签执行痕迹进化 harness，但其五个任务域（text-to-SQL、竞赛编程、SWE 等）**本质全部可验证**，且代理信号无可靠性估计、无回滚、proposer/judge 同一模型（第三方冷评指出的三缺口）。HarnessX/MSCE 的信号仍是基准 verifier 分。**未找到任何"冻结模型、进化 harness/记忆/技能、任务为 deep research/长文写作/工程决策"的工作**——此交集空白成立。

## Reward hacking：必须内置的冷水

- **judge 评的是 plausibility 而非 correctness**（Zhou 2026 实证）：self-play 可把 reference-free judge 通过率刷到 0.94 而真实质量 0.20；**de-anchoring**（judge 先独立作答再评）把假阳性 0.719→0.012，是当前最有效的单点防御。
- **hacking 是结构均衡而非 bug**（五公理证明，2026）：有限评估下不可根除，agentic 系统的评估覆盖率随工具数结构性趋零。
- Rubric Dropout 直接观测到训练 judge 分数上升时 gold judge 分数下跌 22 分——任何不含 de-anchoring/准则随机化的设计应视为默认已被 hack。
- 延迟信号侧：SWE-CI 给出 EvoScore（未来加权功能正确率，度量 repo 长期可维护性）与"技术债第 5 轮才显形"的实证，但**无人把它回流为进化信号并做跨代信用分配**——度量已备好，闭环缺失。

## 立项方向（据 deep_B3 §4）

**RQ**：对冻结权重的 harness 型 agent，在无快速可靠 verifier 的任务域（深度研究、长文写作、长周期工程维护）上，如何构造"可靠性可估计"的复合进化信号，使 harness 进化在第三方审计下真实变好而非 hack 掉自己的评估器？

三个草案：

- **草案 A（SigWeaver-H）**：把 Weaver 的弱监督集成从"选答案"迁移到"选 harness 编辑"——K 路弱信号（de-anchored judge、进化中 rubric、self-consistency、执行痕迹代理、稀疏人类抽查）经在线可靠性估计加权后作为编辑接受函数；可靠性估计器位于进化环外且只读，信号权重对进化 agent 不可见。
- **草案 B（EvoScore-in-the-loop）**：每代 harness 的适应度 = 未来 k 轮 EvoScore 折现和，即把 HGM 的 CMP（谱系聚合表现）从可验证基准分推广到延迟弱信号；弱信号做先验、延迟结果做后验的两阶段信用分配。
- **草案 C（三角审计协议，撞车风险最低、对所有竞品互补）**：回答"进化是否真的变好"——(i) 进化全程不可见的冻结外部锚（held-out gold judge + 人类金标）；(ii) **跨域 canary**：不可验证域分数上涨而旁路可验证任务下跌即判定 hacking（现无先例）；(iii) 时间滞后审计（用进化时不存在的未来数据事后检验）。三锚同过才认定真实进步。

主要风险：评估循环（鸡生蛋）是本质困难，诚实姿态是给出"审计强度 vs 进化压力"的经验边界而非宣称解决；撞车风险高（本题一年内从空白变热点，TTHE/AHE/HOTE 作者组都在一步之遥），时间窗按 3-6 个月估计，建议优先做草案 C。
