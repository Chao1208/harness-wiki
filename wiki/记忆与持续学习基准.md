# 记忆与持续学习基准（Benchmarks for Agent Memory & Lifelong Learning）

> **一句话结论**：change-001 时点的"尚无面向 coding harness 的记忆/lifelong 基准"这一宽表述**已过时**——2025-06 至 2026-08 的 18 个月内该空间被 14+ 个新基准密集填充（MemoryCode、SWE-Bench-CL、SWE-ContextBench、SWE-Milestone、DreamBench-SWE、SkillFlow 等）；但收窄后的**组合空白真实存在**：没有任何基准同时做到"真实仓库跨会话演化 × harness 原生记忆机制作为受控变量 × lifelong 三度量齐备 × live 去污染管线"，缺口矩阵上**每一列都有人做到、没有一行全绿**。两份底稿一致建议 A5（记忆机制基准）与 C6（lifelong 结果基准）合并为一个双 track 基准立项（可再并入 [D1 的 retention 回归协议](harness遗忘与回归.md)），但窗口紧迫（该子领域 8 个月新增 6+ 基准）。

## 基准全景：三个世代

**第一代：对话/用户中心记忆基准**（测"记没记住对话内容"）——DMR（已饱和 94%+）、LoCoMo（合成对话、被刷榜）、LongMemEval（六能力划分成行业标准）、PrefEval、BEAM（ICLR 2026，规模推到 10M token，仍是对话回忆）、HaluMem（首个**操作级**基准：记忆提取/更新/QA 三阶段幻觉率，发现更新阶段正确率 <26%）、MemoryAgentBench（ICLR 2026，增量喂入协议）。共同短板：纯回忆、非执行、与 harness 工作流无关。

**第二代：agent 轨迹/经验记忆基准（2026 爆发带）**——MemoryArena（766 个任务间显式依赖的多会话任务，直接测"记忆→行动"）、LongMemEval-V2（web-agent 轨迹史，25M-115M token，能力分类含 workflow knowledge/gotchas，**LAFS 延迟-准确率前沿计分**是效率一等指标的最成熟实现）、AMA-Bench（ICML 2026）、EvoMemBench（15 记忆系统统一协议横评）、MemTrace（记忆失败归因方法学）。仍非 coding 域。

**第三代：coding/SWE 序列化与经验基准（直接竞品带）**，缺口矩阵如下（据 deep_C6 §3.2）：

| 竞品 | 真实仓库演化 | 跨会话记忆 | 遗忘/保持度量 | 迁移/复用度量 | 污染控制 | harness 原生记忆 |
|---|---|---|---|---|---|---|
| SWE-Bench-CL（2025，仅 arXiv） | ✅ issue 时序 | ✅ 外挂 FAISS | ✅ 最全指标族 | ✅ | ❌ 旧数据 | ❌ |
| SWE-ContextBench（2026） | ✅ issue 引用图 | ✅ 经验池 | ❌ | ✅ 准确/时/费 | ❌ 旧数据 | 部分 |
| SWE-Milestone（**ICML 2026**） | ✅ commit→里程碑 DAG | ❌ 单 session | 部分（P2P 回归惩罚） | ❌ | ✅ | ❌ |
| SWE-CI（2026） | ✅ commit 链（均值 233 天） | ❌ | ❌ | 部分（EvoScore） | 部分 | ❌ |
| EvoCode-Bench（2026） | ❌ 构造任务 | ❌ | 部分 | ❌ | ✅ | ❌ |
| MemTrace-Bench（ICSE'27 在审） | 部分 | ✅ 15 种配置 | ❌ 只测危害 | ❌ | ✅ synthetic twin | 部分 |
| SkillFlow（2026） | ❌ 合成工作流族 | ✅ 技能库 | 部分 | ✅ 技能增益 | ✅ | ✅ **Claude Code skills** |
| DreamBench-SWE（2026） | 部分（注入陷阱） | ✅ | ❌ 只测卫生 | ❌ | ✅ 事实新造 | ❌ |

关键单点结论：SWE-Milestone 证明"孤立任务 >80% vs 连续推进 38%"的巨大落差；MemoryCode（ACL 2025）证明 GPT-4o 全历史在跨会话编码约定上跌 67%；MemTrace-Bench 证明朴素持久记忆有用率 +13.6pp 但过期 API 记忆坏率 18.9%、跨仓库泄漏坏率 22.6%；Evaluating AGENTS.md 证明手写 context 文件仅 +4%、LLM 生成为负且成本 +20%（效应量教训直接决定新基准的统计功效设计）。

## 收窄后的真空白（五个维度逐条核实，据 deep_A5 §3）

1. **跨会话记忆**：❌ 不再空白（6+ 工作），以此立论会被直接拒稿。
2. **跨项目记忆迁移与干扰**：✅ 空白。"用户级偏好应跨项目生效、项目级惯例不应泄漏"这一对偶命题无任何基准，且有天然 harness 语义（user-scope vs repo-scope 文件层级）。
3. **记忆固结正确性**：对话域已有 HaluMem 一系；coding 域仅 DreamBench-SWE（单作者、主对比 null、只测卫生不测固结收益/损伤权衡）→ 部分空白。
4. **写入策略质量（harness 语义）**：✅ 空白。现有工作只测静态文件存在与否；agent 会话中的写入决策（该不该写、写到哪一层、compaction 后能否存活）没有任何基准操纵。
5. **live 污染控制 × 记忆序列**：✅ 组合空白。部件成熟（SWE-bench-Live 月度刷新、SWE-rebench 日期标记协议）但没有任何记忆基准使用 live 任务源；"记忆序列要长期稳定 vs live 源要月度换血"的张力无人正面解决（双轨制：冻结版+live 榜是候选解）。

另一个全场忽略的维度：**记忆与仓库的协同演化**——仓库演化到版本 v+1 后，v 时代沉淀的记忆/技能何时该失效？GitChameleon 证明版本知识漂移是真实失败源，但无基准把"过期记忆的失效时机"作为被测能力。这是 harness 场景（记忆随 git 历史一起长）独有的问题。

## 合并立项判断（A5 + C6 → 单一基准，双/三 track）

两份底稿独立得出相同建议，理由三条：(1) **数据基座完全同构**——都需要"同一真实仓库的时序任务序列 + 显式会话边界 + 持久记忆目录"，分开做重复 RepoLaunch 级工程量且互相竞争新颖性；(2) **指标天然分层**——机制指标（记忆命中、固结正确性、漂移过期率）是结果指标（成功率斜率、遗忘、复用收益）的归因层；(3) **竞品格局逼迫**——单做任一侧都撞 3+ 竞品，只有合取无人占据。

设计草案要点（工作名 HarnessMemBench，详见底稿）：任务序列三源混合（live issue 流 / 里程碑 DAG / 注入式不可推断事实 + 漂移探针）；每任务 fresh session、唯一跨任务通道是 git 版本化的 harness 记忆目录；被测配置横轴从 no-memory 到 Claude Code auto memory 到外挂 Mem0；指标纵轴 = Lifelong track（AA/FWT/BWT/复用率/成本曲线）+ Memory track（写入/固结/检索操作级质量）+ Drift track（过期记忆危害率与自我纠正延迟）。成本量级：core 版 300-500 任务、标注 400-700 人时、全榜单 $2-5 万，须设 lite split。

主要风险：赛道移动极快（SWE-Milestone 团队含 OpenHands 系作者，抢跑概率不低）；harness 差异 20+pp 摆动会淹没记忆效应（须 locked-harness 协议）；净效应可能太小（AGENTS.md 式 ±4% 教训，须区分"记忆可有可无 vs 记忆必要"两种 regime）。
